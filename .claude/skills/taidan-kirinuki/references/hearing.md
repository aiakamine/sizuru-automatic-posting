# ヒアリング（グリルミー）— 対談・解説系切り抜き

制作に入る前に、選定と文言の前提を**ユーザーと認識が一致するまで**詰める。
記録は `$D/hearing.md`（雛形 `templates/hearing.md`）。`状態: 確定` になるまで、
`banner.py` `render.py` `gen_docs.py` は gate_hearing フックが拒否する。

## 進め方のルール

1. **先に素材取得とテロップ走査を裏で走らせる**（subscan は約3〜5分。待ち時間をヒアリングに使う）
2. **`references/learnings.md` と `.claude/skills/SHARED_LEARNINGS.md` を読んでから聞く**。過去のFB・保留中の意見を推奨回答に反映する
3. **1回に1問**。AskUserQuestion で選択肢2〜4個、推奨を先頭にして「（推奨）」を付け、
   description に理由とトレードオフを書く。推奨は素材（タイトル・概要欄・章立て・自動字幕）から作る
4. **曖昧な回答は具体値になるまで掘る**
   - 「おまかせ」→ 推奨を具体値で提示し、それで確定してよいか聞く
   - 「バズりそうなところ」→ 候補を時刻つきで出して選んでもらう
5. **回答同士の矛盾を指摘する**（例：CTAは本編送客なのに、本編を見なくても完結する切り方ばかり）
6. **決まった項目からすぐ `$D/hearing.md` に書く**。会話だけに残さない
7. **最後に要約表を見せて確定を取る** → `状態: 確定`
8. 制作中に前提が崩れたら `状態: 未確定` に戻して聞き直す（フックが再び止める）

## 必須項目と深掘りの観点

見出し名は `templates/hearing.md` とフックの検査で固定されている。変えるときは3か所を同時に直す。

### 本編URL
- 本編（対談・解説動画）のYouTube URL。切り抜き投稿から本編への誘導
  （sns-scheduleでの予約投稿）にもこの値を使うので必須

### 目的とCTA
- 本編への送客が基本（CTA「本編はこちらから」）。別の誘導先（LP・イベント・製品ページ）があるか

### 本数
- 既定6本。お試しなら1本。減らすなら、どの章・実演を優先するか

### 公開チャンネル
- 投稿先チャンネルURL。タイトル・ハッシュタグの実測に使う

### レイアウト実測に使う公開済みショートURL
- 最新の公開済みショート1本（`measure_layout.py` と `extract_cta.py` に使う）
- 無い場合：`references/layout.md` の実測例を使うことをユーザーに確認し、その旨を書く

### 検索需要枠の製品名
- 1本を検索需要の枠にする（SKILL.md 手順3）。候補の製品名と、Google Trends を取り直すか
- 製品を扱わない回なら「該当なし：理由」

### ターゲット視聴者
- 知識レベル（初心者／実務者）・職種・目的。「誰に刺さったら成功か」を1文で

### NG（話題・人物・表現）
- 出演者・会社としてNGな話題、他社製品への言及、誤解を招く断定
- 本人がその場で撤回・訂正した発言を使うかは必ず確認する

### フック方針
- 数字・断定／成果物そのもの／視聴者の疑問の代弁、のどれを軸にするか
- **telops.txt ができたら候補シーンを提示する**：本数×2〜3個のフック候補を表で出す
  （時刻／テロップ原文／画が動いているか／続ける本編／懸念点）。選ばれた組み合わせを記録する

### 尺
- 既定 53〜63秒。フック5〜10秒。プラットフォーム別の希望があるか

### 納品先
- 既定：デスクトップに `<シリーズ名>◯◯_切り抜き◯本_YYYYMMDD`。編集指示・投稿タイトル案の要否

### 個人情報マスクの確認
- 画面共有にメール・ファイル名・顧客名が映る区間の扱い（マスクする／その区間を使わない／本編集に申し送る）
- 過去にドライブのファイル名が未モザイクだった事例あり
