# ヒアリング（グリルミー）— 密着切り抜き

制作に入る前に、選定と文言の前提を**ユーザーと認識が一致するまで**詰める。
記録は `$D/hearing.md`（雛形 `templates/hearing.md`）。`状態: 確定` になるまで、
ベース画像生成と書き出しは gate_hearing フックが拒否する。

## 進め方のルール

1. **先に素材取得とテロップ走査を裏で走らせる**（走査は20分の動画で約8分。待ち時間をヒアリングに使う）
2. **`references/learnings.md` と `.claude/skills/SHARED_LEARNINGS.md` を読んでから聞く**。過去のFB・保留中の意見を推奨回答に反映する
3. **1回に1問**。AskUserQuestion で選択肢2〜4個、推奨を先頭にして「（推奨）」を付け、
   description に理由とトレードオフを書く。推奨は素材（タイトル・概要欄・自動字幕・チャンネル）から作る
4. **曖昧な回答は具体値になるまで掘る**
   - 「おまかせ」「いい感じに」→ 推奨を具体値で提示し、それで確定してよいか聞く
   - 「数字が入ったやつ」→ どの数字か、候補を時刻つきで出して選んでもらう
5. **回答同士の矛盾を指摘する**（例：目的は採用なのに、テーマ候補が顧客向けばかり）
6. **決まった項目からすぐ `$D/hearing.md` に書く**。会話だけに残さない
7. **最後に要約表を見せて確定を取る** → `状態: 確定`
8. 制作中に前提が崩れたら `状態: 未確定` に戻して聞き直す（フックが再び止める）

## 必須項目と深掘りの観点

見出し名は `templates/hearing.md` とフックの検査で固定されている。変えるときは3か所を同時に直す。

### 本編URL
- 素材取得に使う本編（密着動画）のYouTube URL（`yt-dlp`で取得するURLと同じもの）をここに書く。
  切り抜き投稿から本編への誘導（sns-scheduleでの予約投稿）にもこの値を使うので必須

### 目的
- 認知・信頼担保／採用／送客（本編・イベント・LP）のどれか。複数なら優先順位
- 採用なら：募集職種・応募導線（オフ会・フォーム）。送客なら：誘導先と、動画内でどこまで言ってよいか

### 本数
- 既定5本。お試しなら1本。本数を減らすなら、どのテーマを優先するか

### 公開チャンネル
- 投稿先チャンネルURL
- レイアウトとタイトル文法を実測する公開済み密着ショートがあるか（無ければ SKILL.md の実測例を使うと明記）

### ターゲット視聴者
- 年齢層・職種・状態（例：転職を考えている20代営業）。「誰に刺さったら成功か」を1文で

### テーマ候補
- 本数分のテーマ配分（SKILL.md 手順2）。必ず入れたい場面・入れたくない場面
- **telops.txt ができたら候補シーンを提示する**：本数×2〜3個のフック候補を表で出す
  （時刻／テロップ原文／異常性ワード／続けるC2の場面／懸念点）。選ばれた組み合わせを記録する

### NG（話題・人物・表現）
- 出演者・会社としてNGな話題、映してはいけない人物・画面、他社名
- **本人がその場で「冗談」「切り抜かないで」と撤回した発言**は、使うか必ず確認する
- ネガティブに読める文言（赤引用には使わない）、個人情報の映り込み

### フック方針
- 異常性ワード／数字／ギャップ発言のどれを軸にするか
- 強さの許容度：刺激強め（再生重視）か、誠実寄り（ブランド重視）か

### 尺
- 既定 52〜58秒（45〜59秒可）。フックの長さ（6〜13秒）に希望があるか

### 見出し・赤引用の方針
- 見出し2行のトーン（煽り／説明的）、黄色で強調する語の方針
- 赤引用：本編で回収される前向きな一言から選ぶ。候補を2〜3出して選んでもらう

### 納品先
- 既定：デスクトップに `<企画名>_切り抜き◯本_YYYYMMDD/`。投稿タイトル案・編集指示の要否
