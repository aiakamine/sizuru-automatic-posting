# 改善ログ — mitchaku-kirinuki

改善フェーズ（`DREAM.md`）で毎回追記する。**新しい回を上に**書く。
ヒアリングの前に必ず読み、推奨回答と提案の重複チェックに使う。
あわせて `.claude/skills/SHARED_LEARNINGS.md`（スキル共通の学び）も読む。

**この本文には直近3回だけを残す。** 4回目より古い回は `learnings-archive.md` の先頭へ移す。
定量欄は `scripts/learnings_stats.py` が読み、回ごとの推移を出す。

## 書き方

```
## YYYY-MM-DD 素材タイトル（URL）
- 定量：本数=4 そのまま使える=2 手直し=2 使えない=0 QC_NG=0 QC誤検出=3 作り直し=1 書き出し秒=90

- ユーザーFB（良かった／悪かった、その理由）：
- 詰まった点・QC指摘：
- 採用した改善：ID — 対象ファイル — 内容
- 却下した改善：ID — 内容 — 却下理由（**理由が無いものは却下にせず「保留」に書く**）
- 保留・観察中：ID — 内容 — 発生回数（2回目で SKILL.md への昇格を提案する）
```

- **発生回数**：同じ趣旨の指摘が過去に何回出たかを数えて書く。2回目になったら昇格を提案する
- **理由なしの却下は作らない**：選ばれなかっただけの提案は「保留・観察中（発生回数1）」に置き、
  次に同じことが起きたら新しい根拠つきで出し直す
